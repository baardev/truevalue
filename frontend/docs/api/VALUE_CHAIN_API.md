# Value Chain API (Standalone)

## Overview

This document defines a **separate** API surface for the value-chain layer.

It must not share endpoints, output payloads, or storage with the supply-chain API except via shared identifiers (`value_phase_id`, `entity_id`, `country`, `date`).

## Static JSON (Current Implementation)

Generated by:
- `src/value_chain/api/generate_value_chain_data.py`

Output directory:
- `data/value_chain/processed/`

### Files

- `data/value_chain/processed/value_metric_definitions.json`
- `data/value_chain/processed/value_sources.json`
- `data/value_chain/processed/value_metrics.json` (full table export)
- `data/value_chain/processed/value_phase{N}_summary.json` (N = 0..8)
- `data/value_chain/processed/value_ndc_metrics.json` (Tholonic N‑D‑C export)
- `data/value_chain/processed/value_ndc_phase{N}_summary.json` (N = 0..8)

## Future REST Endpoints (FastAPI)

### GET `/api/value/v1/metric-definitions`

Returns available value-chain metrics and their definitions.

### GET `/api/value/v1/sources`

Returns value-chain data sources and coverage.

### GET `/api/value/v1/value-phase/{value_phase_id}/metrics`

Returns value-chain metrics for a phase (filtered by date/entity if provided).

### GET `/api/value/v1/entities`

Returns entity registry filtered to value-layer usage (if needed).

## Key Constraints

- Units are monetary/financial (USD, USD/oz, percent) **only in this layer**.
- Supply-chain UI must not directly consume these endpoints.
- Any reconciliation is explicit and documented.

## Time Resolution

Value-chain metrics support both:

- `period_type = quarterly` (educational/sensitivity)
- `period_type = annual` (broad compatibility)

`date` is always interpreted as the **period end**.
