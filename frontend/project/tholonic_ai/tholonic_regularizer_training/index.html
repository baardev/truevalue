⚗️ Tholonic Balance Regularizer

Training experiment adding a structural balance term to the loss function that penalizes D-C imbalance at every layer simultaneously. Unlike external alignment constraints, this is architecturally constitutive — D-structure is built into the training objective, not imposed from outside after the fact.

Tholonic Balance Regularizer (paper §11.2)
ℒtotal = ℒtask + λ · Σℓ |σDℓ − ½ σCℓ|²
where σ_D^ℓ = RMS activation magnitude of the D-sublayer (normalization) at layer ℓ, σ_C^ℓ = RMS activation magnitude of the C-sublayer (attention + MLP) at layer ℓ. The 1:2 target ratio mirrors the virial theorem equilibrium: ⟨T⟩ = −½⟨V⟩. λ = 0.01 (initial; requires hyperparameter search). This regularizer operates on internal structural organization, not on task outputs — it is not vulnerable to Goodhart's Law.

Explicit N-D-C Layer Structure (paper §11.1)

Each representational level in a tholonically-designed architecture has explicit D, C, and N sublayers. The transformer block already approximates this structure; the experiment makes it explicit and adds the balance regularizer to enforce it.

Baseline Architecture (control)
  • Standard transformer: LayerNorm → Attention → MLP → Residual
  • Loss: cross-entropy (language modeling) or categorical (classification)
  • No explicit D-C balance monitoring
  • D-sublayer exists structurally but is not explicitly tracked
  • Identical initialization, optimizer, and data to treatment
Treatment Architecture (tholonic)
  • Same structure as baseline — no new parameters
  • + ℒ_tholonic regularizer added to training objective
  • + Per-layer σ_D and σ_C tracked during training
  • + D-C balance logged every 100 steps for analysis
  • Same initialization, optimizer, and data as baseline

Experimental Design

Architecture
Small transformer — 6 layers, 256 hidden dim, 4 attention heads. Small enough to train rapidly; large enough to exhibit meaningful D-C dynamics.
Benchmarks
CIFAR-100 (image classification), WikiText-103 (language modeling), WILDS (OOD robustness). Each chosen because ground-truth optimal performance is known.
Matched pairs
5 random seeds × 2 conditions (baseline / tholonic) = 10 runs per benchmark. Same seed, same initialization, same data order — only the loss function differs.
Optimizer
AdamW, lr = 3×10⁻⁴, cosine decay, weight decay 0.1. Batch size 128. Max 50,000 steps. Checkpoint every 1,000 steps.
λ search
Initial λ = 0.01. Grid search over {0.001, 0.005, 0.01, 0.05, 0.1} on a single CIFAR-100 run before the pre-registered experiment. λ fixed before full experiment.
Primary metric
Steps to target validation loss (convergence speed). Secondary: final validation loss, OOD gap, reward-model vs. human-preference gap.

🎲
Pre-register the protocol. Record the exact λ chosen, the exact σ definitions, and the exact benchmarks and metrics before running any treatment conditions. This prevents HARKing (Hypothesizing After Results are Known).
💻
Infrastructure. At minimum, a single GPU (RTX 3090 or better) for the CIFAR-100 runs. WikiText-103 language model requires more memory; a GPU with ≥24 GB VRAM or multi-GPU setup is recommended.

⏳ Status: Pilot Run Complete — Full-Scale Test Pending

A small-scale pilot (SmallGPT 6L d=128, 4,000-character corpus, 3 seeds) shows no difference between baseline and tholonic conditions. This is inconclusive — the corpus is too small for the 0.01-weighted regularizer to have a detectable effect. Both conditions overfit the tiny data at the same rate regardless of structural balance.

The proper test requires: (1) WikiText-103 or CIFAR-100 at 50,000+ steps, (2) a GPU (RTX 3090 or better), (3) pre-registered λ selected via grid search, (4) matched-pair runs across 5 seeds. This is the next step to distinguish "no effect at any scale" from "no effect detectable at toy scale."
